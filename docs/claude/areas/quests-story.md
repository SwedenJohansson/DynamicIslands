## Quests: how steps are defined
- Settings `quest.title`, `quest.intro`, `quest.steps`, `quest.reward`, `quest.done`; further quests `quest2.*` to `quest9.*` (`IslandQuest.Key(key, n)`, `MaxQuests` = 9, n = 0 is the main quest). Read/write with `IslandQuest.From` / `To`.
- `quest.steps`: one line per step, `type|target|count|text`. `IslandQuest.Types`: `reach` (zone id), `read` (note title), `open` (the chest's note title; empty = any), `kill` / `catch` (creature `Kind.Label`), `collect` (story item, `story:<id>` or id), `pages` (empty = this island, `all` = any). `collect` and `pages` are `Counted`. Empty target matches anything. QE1/4/7 (11-03, `QuestSteps.cs`): `signal` (a signal name, or `Name=open|closed|shown|hidden` via `Behaviours.Passes` state check - only while `e.Root` is loaded on the host; `Counted`, polled by `CheckCounted`), `bring` (`Item@Receiver`, count; `QuestSteps.HandIn` from `Islanders.Talked` and `LootCrate.OnIsRayed` via `ChestRayed`: takes from the local player's inventory, then `QuestTracker.Event(e,n,...)` with the amount), `craft` (item, count; Harmony on `CraftingMenu.CraftItem`, `Block_CookingStand.CollectItem`, `CookingTable.PickupFood` -> `QuestSteps.Made`: only the current step, within 300 m, never early). `IslandQuest.MaxStepCount` 99 = the editor's cap (steps in a ScrollList box). 11-04: `fish` (fish item or empty, count; `FishingRod.PullItemsFromSea` Prefix/Postfix + `FishingBaitHandler.GetRandomItemFromCurrentBaitPool` Postfix record the pulled item -> `QuestSteps.Caught`, reach `CraftReach`), `gather` (item or empty, count; `QuestStepsGather` depth-guarded inventory diff (depth left in a Harmony Finalizer, so a throw cannot leave it stuck) around `Pickup`/`PickupChanneling.AddItemToInventory` and `HarvestableTree.Harvest`, only while `GatherWaiting()`, reach `GatherReach` 40 m -> `QuestSteps.Gathered`). Craft, fish and gather credit only the current step (`Credit`), never early.

## Main flow
1. On the acting machine: `TriggerZone.Enter` -> `QuestTracker.Event(e, "reach", Id)`; `NoteReader.Show` -> `read`; `LootCrate.Open` -> `open`. The host's `CreatureSpawner` -> `kill` / `catch`.
2. `QuestTracker.Event` tries every quest of the island: a match on the current step adds progress; a match on a later step is kept (`Remember`, credited by `CreditEarly`). `LaterStep` picks that step: the first later step that names the target (skipping one whose early count is already full), else the first "any" step (empty target).
3. `QuestTracker.Set(e, n, step, progress, send)` stores it and sends `QuestStep` (n = 0) or `QuestStepMore` (n > 0). A client with `IslandNetwork.HostAddsCounts` sets its own view and sends only its amount (`Name` = `add`); the host adds it in `AddFromPlayer` and tells everyone, who call `QuestTracker.Apply`.
4. `collect` / `pages` steps advance in the host's `CheckCounted` (from `QuestTracker.Tick`), only while a player is near (`AnyPlayerNear`; islands without quests are skipped first). `SideQuestOpen(e)` (a side quest begun, not done) keeps `ReturningIslands.Why`/`Finished` from treating the island as done. Per island copy: page keys use `StoryBook.PageIsland(e)`; story items record their source copy (`Held.From`, saved as the 8th `story.item` field) and `Found` subtracts `FoundOnOtherCopies`.
5. Last step: `Completed` -> story items once, on the host (`StoryBook.Give`); Raft items per player via `QuestRewards.OnCompleted` (or later `Collect` in `Tick`). Main quest only: `QuestTracker.Advanced` -> `Behaviours.OnQuestAdvanced` -> on the host, when done, `FireFromHost(e, -1, "quest")`.
6. World plans read it: `WorldDirector.Happened` (`quest`, `step`) and `StoryChain.IsDone`.
7. Behaviours: `Behaviours.Fire` -> checks (`Passes`; failing, `Otherwise` runs the `else.` actions as event `<ev>!`) -> `Run`: personal part on the acting machine (`Schedule` -> `RunPersonal`), shared part on the host (`RunShared`; a client sends `EventFired`). `wait` splits actions into parts.

## Quest text rules (user, 2026-10-27; ROADMAP PQ1-PQ10, guide 6.1 "Writing steps players can follow")

- Step and note texts never use compass sides; they name landmarks a player can see from any arrival side. Each step says plainly what to do and where ("kill the rats", not "free the area"); an item in a crate or chest is said to be in one.
- The first step's place is marked (a gold beam, label "Start: ..."; `Minimap.cs`, the opening message in `Quest.cs`) and the opening message names it. Every island message goes to the journal once.
- Nothing unreachable, no spot to get stuck in: every pit, shaft and cave has a ladder or ramp out; Unstuck works under the sea and after 20 s stuck. Kill steps have a spare creature. `CIReach` (testing.md) walks every target.

## Traps
- Host/client: the acting machine does the personal part (message, Raft items, sound, teleport); the host does shared actions, gives story items once, keeps quest totals, notices kills and catches, and runs `FireFromHost` (`quest`, `defeat`). A chest, a once-zone, or a `read` / `arrive` with a `take` check or `give` / `teleport` asks `Claims.May` first. `StoryBook` changes go to the host, which sends the whole state (`Name` = `all`).
- `read` and `arrive` fire once per world (`DoneBase` key); later reads run messages and sounds only. On the host a shared part runs once per `read` / `arrive` (`SharedOnce`), every time for `trade`, `crowd` and `crowdleft` (each one paid for / one host-decided change; 11-04), and once per second for other events.
- `FireFromHost` drops `has` / `take` checks of Raft items (no player did it); use story items there.
- `QuestTracker.Advanced`, `on.quest`, the `quest` check and the WHEN `step:` use the main quest only; `quest:<ref>:<n>` rules use `QuestTracker.IsDone(e, n)`.
- `QuestTracker.Set` never moves back; a stale message returns false and the host does not pass it on.
- Steps and checks match by name (zone id, note title, creature `Kind.Label`; case-insensitive). `EditorRenames` (player 10-30) moves quest `read`/`open` steps with a note/chest title and `reach` steps with a zone id (ObjectInspector, `NoteEditorWindow.Apply`; appended to the rename's undo step; skipped while another object keeps the old name); `StoryItemsWindow.SaveDefs` renames a changed story id via `StoryItems.RenameUses` (island) + `RenameRefs` (objects). `ObjectName` moves `obj.name` action targets, named checks, `cam.look` and `talk` steps; `RuleRefs` the island's own `bring.rules`. Creature kinds (fixed by the placed object), signal names and world plan files are not followed. `StoryItemsWindow.CleanId` folds accents (FormD) and the id field refuses an id that cleans to "" with a Notify. Zone and chest keys use their ordinal in file order.
- A chest holding story items never refills (`LootCrate.Attach`). A zone with story items is not re-armed by `LootCrate.OnIslandReady`, and a zone that fires on every walk-in gives its story items the first time only (`TriggerZone`: `fired`).
- The quest editor reads `IslandQuest.From(props, n, true)` (raw); without `raw` texts are made plain for showing.
- Editor tables (`TypeLabels`, `VerbLabels`, `CheckLabels` and their hints) are indexed directly: a new type, verb or kind without an entry throws.
- `PendingKey` packs the event number in 4 bits (`ObjectEvents` + `IslandEvents`, the `!` variants after them): new events renumber saved pending keys, and more than 8 events overflow (already 10 today: the late `!` variants clash; pre-existing). New resumable events go in `PlayerFeatures.ResumableEvents` (0xA00000) instead.
- Atmosphere and sound zones act per machine only (no state, no network).
- C# 7.3: no switch expressions, `??=`, ranges or `using var`.
- Docs: docs/GUIDE.md `5.2` to `5.5`, `6.1 Quests`, `6.2 Behaviour and events`, `6.3 Story items and story sets`; README.md `### Source overview`.

- Spent survivor keys: `Behaviours.Holds` adds `Survivors.KeysSpent(e, id)` to a story item's count for `has` (not `take`): keys used up on opened survivor cages of the same island (survivor.key = id, `ContentState.IsUsed(e, Survivors.KeyBase + index)`). Fixes key-on-cage-first softlocks (Lowstreet cagerelease, Cirrus Silo Farm silohatch, 11-07). Recipes for 3.1 worlds also use `any` + `signal|<cage signal>` on the lock.
